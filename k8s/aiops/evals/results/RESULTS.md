## Reading of the result

- The SLM gives up **7.2 points** of top-1 accuracy on model-routed incidents and returns **160x** lower inference cost and **4.0x** lower p90 latency.
- Schema validity goes the other way. Constrained decoding on the local server gives 100.0% first-try contract compliance against 95.0% for the baseline. An unparseable RCA is an outage in the automation, not a soft quality loss.
- Every proposed action landed inside the cause-scoped allow list. That is the number an SRE reviewer should care about most, because it bounds what a wrong diagnosis can do.
- Both engines were scored against the same golden set and the same policy file. The comparison is apples to apples by construction.

## Known misses, kept deliberately

The SLM misclassifies the two incidents where the distinguishing signal is a *comparison across scopes* rather than a threshold on one series: dependency latency attributed to the caller (INC-009) and single-node contention read as generic CPU throttling (INC-019). Both fail into `propose_resource_limit_change`, which is inside policy and human-gated, so the failure mode is a wasted approval rather than a bad change. These stay in the golden set as the next fine-tuning target.
